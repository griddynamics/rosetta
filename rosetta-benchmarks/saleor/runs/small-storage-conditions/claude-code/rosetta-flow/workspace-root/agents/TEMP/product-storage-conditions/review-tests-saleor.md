# Review: BE tests (T1) vs SPECS/PLAN

TLDR: No blocker. Coverage of BE-03..BE-11 is good and the tests assert real behavior. 2 minor gaps, 1 spec gap (bulk translate error code), 1 optional migration test. Spot-check: 9 new tests pass (reuse-db). Mutation reasoning: dropping the strip, the translation_fields entry, or the category guard each makes a named test fail.

Findings
- major-1 (spec gap + pre-existing prod behavior, not a T1 defect): test_product_bulk_translate.py:~475-495 asserts a protocol-level error for >250. The code `max_length` is not in ProductTranslateErrorCode (core/enums.py:413). SPECS section 6 says "row error". `name` >250 behaves the same, so it is a spec wording gap. Fix: change SPECS section 6 and BE-07 to "bulk >250 rejected (request-level GraphQL error, nothing saved; same as name)". Do not change production code: a fix would need MAX_LENGTH added to a public error enum (schema change) or a mapping in product_bulk_translate.py, which is scope creep that needs user approval. Keep the test; it pins the actual behavior and the nothing-saved invariant.
- minor-1: no migration test (BE-02). The repo has no migration tests, and V1 plus `makemigrations --check` cover it. Acceptable. Only the reverse is unproven, so optionally run `migrate product 0210` and `migrate product 0211` on a throwaway DB.
- minor-2 (coverage): (a) bulk create has no padded 251/250 case and no no-permission test (test_product_bulk_create.py:565-625); (b) category/collection translate with whitespace "   " is untested (spec says "non-empty", and the guard rejects it); (c) no BE-12 assertion that PRODUCT_SEARCH_FIELDS is unchanged (optional).
- minor-3 (weak assertion): test_category_translate.py:~137 and test_collection_translate.py:~137 use `data["category"] is None or ...["translation"] is None`. The following `not translations.exists()` check is the real one. Replace with a single `is None` check once the actual value is known.
- minor-4: the CSV test_export.py case ends with `shutil.rmtree(tmpdir)`, matching its neighbours. No isolation problem.
- Compliance: the only changed existing assertions are test_get_products_data's expected_data (+storage_conditions) and its setup. Mocks: none, and none are needed. Fixtures and given/when/then match their neighbours. Create/update both cover strip, blank, null, 250, padded 250, 251, unicode, html, omitted key and no-permission. Translation not-stripped is covered. Anonymous read is covered. Webhook (value and null) and translation key are covered. CSV covers header order, per-variant repeat and empty cell.
- mypy noise (105 errors on tests, same enum pattern as existing tests): acceptable, pre-existing class. Do not fix it in this change. Note it in the report.
