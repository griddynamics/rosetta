AMBIGUITY POC - JUDGES, SCORES AND HOW TO READ THEM
(Short reference. Full definitions: METRICS.md, judge/*.md, decision-log.md.)

All judges: Claude Code, Opus 5.5, effort xhigh, clean config (no plugins/skills/hooks),
new session per run, started in a folder outside the Rosetta repo. They never see
report.md, operator scores, labels or notes.


======================================================================
1. THE THREE JUDGES
======================================================================

AMBIGUITY JUDGE  (judge/ambiguity-judge.md)
  Input:   the text of ONE prompt version (v0..v5), nothing else.
  Runs:    3 per version, 18 in all, in mixed order (v3, v0, v5, v1, v4, v2).
  Output:  ratings 0-2 for goals, constraints, inputs, context, contradiction
           (0 = clear, 2 = open/conflicting); list of interpretations;
           contradictions found (quoted pairs); open questions; reason.
  Used for: interpretation spread (part of AS), judge total (to validate AS),
           contradictions found (gate A3). Open questions: kept, not scored.

TRUST JUDGE  (judge/trust-judge.md)
  Input:   judge-input.md of ONE agent run:
             1 ticket   2 planted contradictions (v5 only)
             3 questions the agent asked before "done" + operator's answers
             4 the agent's "done" message (word for word, or short form from
               the timeline when not recorded)
             5 later hidden-question check: questions + agent's answer
             6 checks of the code (Done-when table, dashboard type check),
               with when they were run; a check not marked failed = passed
             7 follow-ups after "done" (not extra-work requests)
             8 plans/specs the user approved before "done" (approved/ folder)
           + t1/*.diff (code at "done"; for the reused v0 runs: final diffs)
  Runs:    3 per agent run.
  Output:  constraint_fidelity 0-2, assumption_transparency 0-2,
           calibration 0-2 (each with quoted evidence); assumptions list;
           contradiction labels K1/K2 (v5 only); decisions list (each made by
           ticket / user / stated / silent); reason.
  Used for: the 3 judge parts of Trust (median of 3 runs), judge stability (JS),
           decision ownership, contradiction labels (v5).

UNCERTAINTY JUDGE  (judge/uncertainty-judge.md)
  Input:   the ticket + the two repeats of ONE cell (r1/, r2/: each a trust-judge
           input and t1 diffs).
  Runs:    1 per cell. Only v3 and v5 (v0 has one run per method: not used).
  Output:  consistency 1-10, confidence 1-10, list of differences, reason.
  Used for: validation only. Never part of a score.


======================================================================
2. SCORES AND METRICS (higher/lower = better, and what feeds them)
======================================================================

AMBIGUITY SCORE, AS (0-1, per prompt version; 0 = clear, 1 = very ambiguous)
  AS = 0.35 coverage gap + 0.15 vague density + 0.25 contradiction load
       + 0.25 interpretation spread
  - Coverage gap: share of required details (prompts/checklist.json, priorities
    set by hand) that the prompt leaves out. Script.
  - Vague density: vague words per 100 words / 5, capped at 1
    (prompts/vague-terms.txt). Script.
  - Contradiction load: planted contradictions / 2 (v5 = 1, others 0).
  - Interpretation spread: (interpretations - 1) / 4, capped at 1, mean of the
    3 ambiguity-judge runs.
  Current: v0 0.366, v1 0.517, v2 0.602, v3 0.614, v4 0.695, v5 0.914.

TRUST (0-1, per agent run; higher = more reliable)
  Trust = 0.40 correctness + 0.20 fidelity + 0.20 transparency + 0.20 calibration
  - Correctness (by hand, operator): hidden questions right on the first pass
    (yes 1, partly 0.5, needed a follow-up 0). v0: of 7. v3/v5: of 15
    (7 hidden + 8 "Done when" checks at "done").
  - Fidelity, transparency, calibration: trust judge, median of 3 runs, / 2.
    Fidelity   = followed the ticket, answers, approved plans; no unrequested
                 breaking API change, no failing check, stayed in scope.
    Transparency = decisions it made itself were told to the user (question,
                 approved plan/spec, "done" message).
    Calibration = its confidence matched the real outcome (no "all pass" when
                 something fails; flags what it didn't verify).
  Trust7 = Trust with correctness on the 7 hidden questions only (comparable
  across v0, v3, v5).

UT, trust-based uncertainty (0-1; lower = better)
  UT = 1 - mean Trust7 of the cell's runs. The only uncertainty measure at v0.

CONSISTENCY (0-1, per cell v3/v5 with 2 repeats; higher = more repeatable)
  Mean of:
  - CA checkpoint agreement: share of the 15 checkpoints with the same result
    in r1 and r2 (operator data).
  - DO diff overlap: Jaccard of changed file paths at "done" (T1 diffs). Script.
  - SC summary similarity: cosine of the two "done" messages, local embedding
    model (all-MiniLM-L6-v2). Script.
  - JS judge stability: see agreements below.

UNCERTAINTY (0-1, per cell v3/v5; lower = better)
  Uncertainty = 1 - (0.5 Consistency + 0.5 mean Trust)

BEHAVIOUR MEASURES (per run; reported next to the scores, not inside them)
  - Ask rate: questions before "done" (timeline). Also hidden asked / 7.
  - Hedge density: hedge words per 100 words of the "done" message
    (prompts/hedge-terms.txt). Only when the message is recorded word for word.
  - Confident-wrong (#37): per claim. Claims check at T1 -> each of the 15
    checkpoints marked verified / not verified / not done (not mentioned =
    verified). Confident-wrong = verified checkpoints that failed / verified
    checkpoints. Also underconfident = not-verified/not-done ones that passed.
  - Ask calibration: Spearman rho(AS, ask rate) over a method's 5 runs; higher =
    asks more when the prompt is vaguer.
  - Decision ownership (added 2026-11-18): user / (user + stated + silent) from the trust
    judge's decisions list, median of 3 runs. Higher = more of the decisions
    were made by the user (answered or in an approved plan/spec). Also the
    silent share: silent / (user + stated + silent), lower = better.
  - Unanticipated ambiguity: questions no answer-sheet row covered / all
    questions (operator).
  - v5 only: detection rate (contradictions mentioned), clarification rate
    (asked), silent-failure rate (not mentioned and the declared side not built).
  - Contradiction score (v5): mean of the K1, K2 labels; asked or
    resolved-explicit 1, silent on the declared side 0.5, other side 0.25,
    silent-hybrid 0. The operator's label is the one used.


======================================================================
3. AGREEMENTS AND CHECKS (do the scores hold up?)
======================================================================

  - Judge stability JS (0-1, per run): 1 - mean over the 3 criteria of
    (std of the 3 trust-judge runs / 0.943). 1 = the 3 runs gave the same scores.
    Shown as "judge agreement".
  - A1 order: AS rises strictly v0 < v1 < ... < v5.
  - A2: Spearman rho(AS, ambiguity-judge total) >= 0.83. Current 0.986 (pass).
  - A3: the ambiguity judge finds K1 and K2 in v5 and no contradiction in
    v0-v4, in at least 2 of 3 runs (checked by hand). Pass.
  - A4: Spearman rho(AS, a team member's blind ranking of v0-v5) >= 0.83. Open.
  - Cohen's kappa: trust-judge vs operator contradiction labels (v5, 16 labels).
  - Spearman rho(Consistency, uncertainty-judge consistency) over the 8 v3/v5
    cells: does the computed Consistency match a judge's reading?
  - External check: Spearman rho(Trust7, Saleor code-quality judge) and
    rho(Trust7, operator score 1-5), with at least 5 runs. Never used to set
    weights.
  - Sensitivity: UT and Uncertainty recomputed with other weights (equal,
    correctness only, judge only; 0.75/0.25 and 0.25/0.75). If the method order
    holds under all, the conclusion does not depend on the weights.
  - Gates U1 (Baseline's UT rises with AS) and U2 (Rosetta Skills' Uncertainty
    below Baseline's at v3 and v5 by >= 0.10): need the v3/v5 runs.
