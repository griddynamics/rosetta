# plugin-generator — Requirements Index

Reverse-engineered requirements for the Rosetta plugin generator: the build step that transforms instruction folders (`instructions/<release>/<folder>/`) into IDE plugin distributions — one per (plugin-set variant × IDE target) pair. Source of truth for a clean re-implementation (target runtime: TypeScript, run via `npx`).

Grep a header below for a one-line description and the file it lives in.

## Files

### SCOPE.md — In/out of scope, actors, entry points, goals, non-goals, global constraints.
### GLOSSARY.md — Domain terms: release, domain, plugin variant, target, bootstrap hook, template, standalone.
### MODEL.md — Configuration contract: release, plugin-target, plugin-set and profile descriptors, and the `src/rosettify-plugins/plugins/<template>-<ide>` preserved-file source location (`DATA-*`).
### FR-ARCH.md — The single normative architecture: uniform spec contract, immutable flat VFS with structural sharing, filename directives, and the **two-tier** pure processor pipeline — `FileProcessor`s over a `FileProcessingFrame` (`fileRename` path-only) and `PluginProcessor`s over a `PluginProcessingFrame` (`pluginRewriteReferences` content-only, by lookup over the per-file frames); no imperative pre/post passes (`FR-ARCH-*`).
### FR-CLI.md — Invocation, release selection, plugin-set configuration (`--config`), the `--domain` folder filter over sets, run modes (dry-run/verbose), orchestration, exit status (`FR-CLI-*`).
### FR-COPY.md — As-is behaviors recast onto FR-ARCH: preserved-file seeding (`pluginCopy`), output reset (`pluginCleanup`), copy (`fileRead`/`pluginWrite`), model normalization (per-vocabulary processors), folder placement (`SpecEntry` `target`) and suffix renames (`fileRename`), content reference rewriting (`pluginRewriteReferences`), alternate-name duplication (`SpecEntry`), and the generator's shared workflow-to-skill conversion for `core-codex` and `core-antigravity` outputs (`FR-SEED-*`, `FR-COPY-*`).
### FR-GEN.md — Folder index generation and template rendering (`FR-GEN-*`).
### FR-HOOK.md — Per-target bootstrap-context payload assembly and hook-bundle synchronization (`FR-HOOK-*`).
### FR-VAR.md — Per-target structure, reasoning, and bootstrap-delivery strategy (hooks vs native rules vs auto-loaded instructions), incl. two-hook-set rationale; per-variant output properties (`FR-VAR-*`).
### FR-SET.md — Plugin sets: `plugins.json` resolution and fail-fast validation, set-to-folder layering, per-set variants, `<set>-<ide>` destination naming, `requires` metadata, single-call generation of every set, and the per-set bootstrap flag and hook list (`FR-SET-*`).
### FR-PROF.md — Profile capability: descriptor resolution and validation, effective model vocabulary, exhaustive per-target candidate skipping, the boundary keeping destination and manifest identity out of a profile, and the profile filename-directive token (`FR-PROF-*`).
### NFR.md — Non-functional requirements: parity, determinism, idempotency, portability, limits (`NFR-*`).
### REFERENCES.md — Authoritative per-IDE configuration guides to consult under `instructions/r3/core/skills/harness/references/configure/` for plugin/subagent/skill/command/rule/hook structure and links (`INT-IDE-*`).
### STRUCTURES.md — Generalized example folder structure per IDE target, parameterized by plugin set (preserved vs generated, with provenance) (`FR-STRUCT-*`).
### ASSUMPTIONS.md — Assumptions, flagged implementation accidents/quirks, open questions.
### TRACE.md — Goal-to-requirement-to-criteria traceability matrix.

### CHANGES.md — Requirement change log with reconciliation history (date, IDs affected, before/after, baseline evidence).

## Status

Requirements describe the behavior of **`npx -y rosettify-plugins@latest`** (`src/rosettify-plugins/`), unified onto FR-ARCH. The as-is behavior FRs were reverse-engineered from the old Python generator (now removed) and recast as processors/`SpecEntry` data — that generator is no longer the parity reference; `src/rosettify-plugins/` is. NFR-0001 (per-target structural parity) is verified per target by comparing each generated output file-path set to the layout derived from the instruction source and that target's mapping contract — path/structure only, not content (byte-for-byte parity was retired with the old generator, whose gitignored snapshot baselines are no longer produced).
- **Behavior carried over from the Python generator (recast onto FR-ARCH)** — FR-CLI (core), FR-COPY, FR-GEN, FR-HOOK, FR-VAR, FR-STRUCT, MODEL, most NFR.
- **New / target-state design** — FR-ARCH (whole): two-tier processors, FR-ARCH-0005 (no identity branching / no identity-discriminant flags; variation by composition), FR-ARCH-0014 (immutability + structural sharing), 0030/0039 (`FileProcessingFrame`/`PluginProcessingFrame`), 0035 (every step a processor; no pre/post passes), 0043 (`fileRename` path-only), 0049 (`pluginRewriteReferences` by frame lookup), 0052/0053/0054 (`pluginCleanup`/`pluginCopy`/`pluginProcessSpecEntries`), 0055 (`pluginAssembleBootstrap`); FR-CLI-0012 (deterministic-hooks override), FR-CLI-0030/0031 (`--domain` + bundling), FR-CLI-0040 (uniform generation), FR-CLI-0050/0051 (dry-run/verbose); FR-HOOK-0009 (explicit, significant bootstrap-file order); FR-VAR-0050/0051 (standalones uniform-from-source), FR-VAR-0070/0071/0072 (bootstrap delivery); NFR-0007/0008/0010 (modularity, TS/npx, libraries); INT-IDE (guide references).
- **`codex` output** — FR-COPY-0080 and FR-VAR-0041/0042 require the generator to map workflows into `.agents/skills/` and emit body-only phase files.
- **Plugin sets (ticket #315)** — `instructions/r3/core/` splits into `core`, `workflows`, `qe`, `search` and `modernization`, and one invocation builds every declared plugin set for every IDE target from `src/rosettify-plugins/plugins.json`: new FR-SET (whole area), DATA-CFG-0007 (plugin-set descriptor), FR-CLI-0034 (`--config`), FR-ARCH-0025 (`set-<id>-only`). IDE target ids lose the `core-` prefix, output folders become `<set>-<ide>` plus the variant suffix, the three suffix fields move from the profile descriptor to the set variant (FR-PROF-0020/0021 restated to forbid them), preserved config folders collapse to five shared `template-<ide>` folders, hooks render from a per-set declared list, and folder-index generation is retained but dormant (FR-GEN-0001..0004). `configure/` is retired; the 8 IDE guides live under `skills/harness/references/configure/`.
- **Antigravity target (ticket #138)** — a single combined `antigravity` target for all three Antigravity products (Antigravity, Antigravity CLI, Antigravity IDE): DATA-CFG-0003 (a sixth then a seventh IDE target), FR-VAR-0080–0083 (combined-plugin output, content mapping, always-on-rule bootstrap, PreInvocation hook template), shared FR-COPY-0080 (workflow→skill), and Antigravity-only FR-COPY-0081/0082 (frontmatter reduction, `subagent_required_model`→`inherit`). No separate standalone target. Gemini CLI deprecated (superseded by Antigravity CLI). Grounded on antigravity.google.
