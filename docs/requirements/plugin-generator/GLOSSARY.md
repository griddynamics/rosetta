# plugin-generator — Glossary

One meaning per term. Used consistently across all requirement files.

- **Release** — A versioned line of instructions (`r2`, `r3`). Selects the instruction source line and a set of template variables. Default `r3`.
- **Domain / instruction folder** — A top-level folder under a release holding instruction content (`core`, `workflows`, `qe`, `search`, `modernization`, or an organization's own folder such as `acme`). Organization content is a declared set like any other, never an overlay layer on top of one. A plugin set names the folders it is composed of; the `--domain` argument no longer selects a layer but filters which sets build (FR-CLI-0030). One folder's tree resolves to `instructions/<release>/<folder>/`.
- **PluginSet** — One declared plugin composition, identified by a `name` and defined by the instruction folders it layers, its variants, its preserved-file template, its manifest fields, its `requires` list, and its bootstrap flag and hook list (DATA-CFG-0007). The declared sets are `rosetta`, `core`, `workflows`, `qe`, `search`, `modernization`. Set is the dimension orthogonal to IDE target: one built plugin is one (set variant × IDE target) pair.
- **SetVariant** — One build of a set, naming the profile it builds with (a profile name or none) and carrying the destination, plugin-name and plugin-description suffixes that distinguish it from that set's other variants (FR-SET-0030). Suffixes belong to the variant, never to a profile.
- **requires** — A set's list of set names expected to be installed alongside it. Metadata only: it drives the manifest description and nothing else, because no target IDE enforces plugin dependencies (FR-SET-0050). It never adds files to the requiring set.
- **Preserved-file template** — The shared preserved-file folder a set seeds from, `<preservedFilesSource>/<template>-<ide>/`. Several sets may name one template, so the preserved source holds one folder per (template × main IDE target) pair and never one per set (DATA-CFG-0005).
- **Profile** — A named configuration axis orthogonal to release and to plugin set, named by a set variant and loaded from `<profileSource>/<name>.json`; `--profile <name>` overrides the profile of every variant in a run. It selects an effective model vocabulary (per-target model overrides) and participates in filename-directive resolution through its own `ProfileOnlyToken`, and nothing else — destination and manifest suffixing belong to the variant (FR-PROF-0020, FR-PROF-0021). An empty descriptor `{}` is valid: its whole effect is then to activate that profile's `profile-<name>-only` files. A variant naming no profile is unchanged from having no profile at all.
- **Instruction source** — The resolved, possibly merged, tree of instruction files (`agents/`, `rules/`, `skills/`, `workflows/`) used as input for one plugin set, layered from the folders that set declares (FR-SET-0020). There is no `configure/` folder: the per-IDE guides live under `skills/harness/references/configure/`. There is no `templates/` folder in any plugin.
- **Layer merge** — Combining the folders one set declares, in the order its `folders` list gives them, so a later folder's contribution bundles onto an earlier one at the same relative path and an `overwrite` directive prunes the earlier ones (FR-SET-0020, FR-ARCH-0042). The merge is internal to a set; there is no overlay-domain axis stacked on top of a base domain.
- **IDE target** — One IDE delivery mode. Each target has a fixed `name` — `claude`, `cursor`, `copilot`, `codex`, `cursor-standalone`, `copilot-standalone`, `antigravity` — used as its stable identity and as the value a `TargetOnlyToken` matches. The `name` carries neither a set name nor a variant suffix; only the `destination` does, as `<set-name>-<name>` plus the variant's destination suffix (FR-SET-0040), so every `target-<id>-only` directive keeps matching whatever set or profile is building.
- **Plugin** — One generated distribution: one (set variant × IDE target) pair.
- **Standalone** — A target whose output is laid out under the IDE's in-repo subfolder (`.cursor/`, `.github/`) for direct extraction into a project, as opposed to marketplace installation. Differs from a "main" target only by its transform spec and output layout, not by how it is generated.
- **Antigravity** — Google's AI IDE family. Three products — Antigravity, Antigravity CLI, Antigravity IDE — all read a plugin's root `plugin.json`. Rosetta ships one combined `antigravity` target that serves all three; there is no separate Antigravity standalone target (in-repo use is achieved by extracting the plugin, whose extra `plugin.json` the IDE ignores).
- **Always-on rule** — An Antigravity rule carrying `trigger: always_on` frontmatter, auto-loaded on every interaction. Rosetta uses it to deliver the bootstrap context for Antigravity (which has no session-start hook).
- **Workflow-to-skill transform** — The generator transform configured for the `codex` and `antigravity` targets (FR-COPY-0080), turning each Rosetta workflow into `<skills-root>/<name>/SKILL.md`, emitting body-only phase files under `<skills-root>/<name>/phases/`, and rewriting actual phase references for their new location.
- **Preserved file** — A file a target keeps but does not generate from the instruction source: the IDE manifest (`plugin.json`), hook templates (`*.tmpl`), IDE config-folder contents, and any `.mcp.json`. It does not "survive" the wipe; `pluginCleanup` empties the output and `pluginCopy` re-seeds it each run from the preserved-file source.
- **Preserved-file source** — The committed input under `<effective preserved-file source>/<template>-<ide>/` (default root `src/rosettify-plugins/plugins/`), mirroring the output-relative layout, that holds all of a plugin's preserved files. The effective preserved-file source is the authority for those files and is copied into the target output before generation so a target can be built into a clean or empty output directory (DATA-CFG-0005, FR-SEED-0001, FR-CLI-0060).
- **Effective preserved-file source** — The preserved-file root actually used, after applying the `--pluginsSource` CLI override where supplied, otherwise the default committed root `src/rosettify-plugins/plugins/`. Preserved-file seeding reads this root (DATA-CFG-0005, FR-CLI-0060).
- **Model normalization** — Rewriting a source document's frontmatter `model:` value into the target IDE's model vocabulary.
- **Agent file** — A document under `agents/<name>.md` describing a subagent.
- **Bootstrap files** — The **ordered** set of rule documents whose stripped bodies are embedded into a plugin's session-start context, declared as an explicit ordered manifest (the `Bootstrap file manifest`). No index document is a bootstrap file (FR-HOOK-0004). Order is significant and `plugin-files-mode` leads. Only a set declaring the bootstrap flag assembles them (FR-SET-0070).
- **Bootstrap context payload** — The per-target, IDE-shaped session-start hook entries that inject bootstrap file bodies into the agent's context, emitted in the bootstrap-file-manifest order.
- **Bootstrap prefix (removed, FR-HOOK-0003 Deprecated)** — Formerly a fixed lead-in string attached to the one designated lead bootstrap document of each target (the first bootstrap-classified entry in the manifest). Removed 2026-07-28: session-start hooks are now small and `get_context_instructions` is no longer used in this flow. Every document's body is emitted as-is, with a leading-newline strip applied uniformly to all entries; there is no longer any lead designation (FR-HOOK-0009).
- **Template** — A Handlebars source file (`*.tmpl`) rendered to a sibling file with the `.tmpl` suffix removed, using release variables plus bootstrap payload values.
- **Hook bundle** — A pre-compiled per-IDE runtime hook artifact consumed from `src/hooks/dist/` and copied into a target's hook folder.
- **Deterministic hooks** — A per-release flag selecting whether the hooks a set declares (and their bundles) are included (`r2`: off; `r3`: on). Overridable per run by a CLI argument, whose default is false (FR-CLI-0012). Which hooks a set declares is separate (FR-SET-0070).
- **Effective deterministic-hooks value** — The `deterministic_hooks` value after applying the CLI override where supplied, otherwise the release descriptor value. All gating and rendering reads this value (FR-CLI-0012, FR-HOOK-0020).
- **Effective model vocabulary** — The model map actually consulted after model selection: the built-in per-IDE `ModelVocabulary`, or — when a profile is active and declares a block for the target — that profile's per-target block, which replaces the built-in map entirely. Model selection is unchanged; only the map consulted afterward differs (FR-PROF-0010, FR-COPY-0020/0021/0022).
- **Folder index (dormant)** — A generated `INDEX.md` listing a folder's documents with descriptions. The capability is retained (FR-GEN-0001..0004) but no plugin set declares one, so no `INDEX.md` reaches any output and no bootstrap payload carries one: an index can only list its own plugin's documents and would misrepresent a multi-plugin install.
- **Transform spec** — The declarative per-plugin description of all adaptations (renames, normalizations, templates, layouts) applied to produce one (set variant × IDE target) pair. See `MODEL.md`.
- **VirtualFile** — One entry in the VFS: a single prospective output file at a VFS path, holding an ordered collection of `SourceFile`s plus, during processing, its resolved target path, binary flag, and target contents. Class name: `VirtualFile`. (Rewrite term; use instead of the bare word "file".)
- **SourceFile** — One physical source file contributing to a `VirtualFile`: carries its absolute origin path, frontmatter, order key, and conditions. Class name: `SourceFile`. (Rewrite term.)
- **target_contents** — The resolved content a `pluginWrite()` would emit for a `VirtualFile`, with three distinct states: `null` = content removed (no file is written); `""` = file is written with empty main content (optional frontmatter only); a string or byte array = file is written with that content.

## Canonical type names (rewrite)

Precise terminology applies to **every** concept, not only files (FR-ARCH-0003). Each concept below maps to one named type:

- **PluginTarget** — one IDE delivery mode, identified by its bare IDE `name`. Use instead of bare "plugin"/"target".
- **PluginSpec** — one plugin's full specification: the descriptor fields (IDE identity, output location and base subfolder, preserved-file seed source, `ModelVocabulary`, bootstrap manifest, the building set's bootstrap flag and hook list, injection declarations) plus an ordered list of `SpecEntry` and an ordered `PluginProcessor` pipeline. It declares no index.
- **SpecEntry** — `{source: glob, target: path, exclude: string[], processors: FileProcessor[]}`. The `target` is the destination folder (folder placement, e.g. `workflows`→`commands`); a filename/suffix change is a `fileRename()` `FileProcessor` in the entry; `exclude` lists VFS paths matched by `source` that must not be emitted (no source rename needed — the source files stay as-is for MCP and instruction references).
- **FileProcessor** — one pure, single-responsibility **file-tier** stage operating on a `FileProcessingFrame` (`fileRead`, `fileApplyOverrides`, `fileBundle`, per-vocabulary model-normalization processors, `fileRename`, `fileCodexAgentFormat`). `fileRename` changes only the path; `fileRead` is the only content ingress. Behavior that differs by case is a separate **case-specific processor** composed into the relevant spec's pipeline, not a branch (FR-ARCH-0005).
- **PluginProcessor** — one pure **plugin-tier** stage operating on a `PluginProcessingFrame` with whole-plugin visibility (`pluginCleanup`, `pluginCopy`, `pluginProcessSpecEntries`, `pluginRewriteReferences`, `pluginGenerateIndexes`, `pluginEmitDistributionRoot`, `pluginAssembleHooksJson`, `pluginRenderTemplates`, `pluginWrite`). `pluginRewriteReferences` changes only content; `pluginWrite` is the only content egress.
- **FileProcessorPipeline / PluginPipeline** — ordered lists of `FileProcessor`s (within a `SpecEntry`) and `PluginProcessor`s (the `PluginSpec` pipeline) respectively.
- **Case-specific processor** — a `FileProcessor`/`PluginProcessor` written for one case (e.g. one IDE's hook entry shape or model vocabulary) and placed only in the pipeline(s) of the `PluginSpec`(s) that need it. The applicable case is selected by which processor a spec composes — not by a runtime branch. Logic common to several case-specific processors lives in shared low-level functions they compose (FR-ARCH-0005).
- **Identity-discriminant flag (forbidden)** — a descriptor/`PluginSpec` value whose value set enumerates IDE/target/case identities (e.g. `hookEntryShape`, `ModelVocabulary.kind`) or is otherwise derived from identity. It is the target name relabeled; branching on it is prohibited (FR-ARCH-0004, FR-ARCH-0005).
- **Genuine behavior flag (permitted)** — a `PluginSpec` value whose value set names a capability or outcome, not an identity (e.g. a deterministic-hooks toggle, a bootstrap/index-inclusion flag). Branching may rest on such a flag. Contrast with an identity-discriminant flag, which is forbidden (FR-ARCH-0005).
- **pluginCleanup (output wipe)** — the head `PluginProcessor` that empties a target output before seeding. Per-file removal of a prospective output is expressed by a processor setting `target_contents` to `null` so `pluginWrite()` produces no file. Nothing "survives the wipe": preserved files are re-established each run by `pluginCopy`.
- **pluginCopy (preserved-file seeding)** — the `PluginProcessor` that copies a plugin's committed preserved files from `src/rosettify-plugins/plugins/<template>-<ide>/` into the output before instruction-derived content is produced; the seed source is the sole authority for them.
- **Bootstrap file manifest** — the ordered list of bootstrap rule documents, and no index document, whose bodies feed a plugin's session-start context. Its order is significant (see below): it fixes both the payload entry sequence and which document is treated as lead (first present entry; only its leading newline is stripped — the removed bootstrap prefix no longer applies, FR-HOOK-0003 Deprecated).
- **FileProcessingFrame** — the per-file mutable working object passed through a `FileProcessorPipeline`: `{sourcePath, target, isBinary, target_contents, source: SourceFile[]}`. Distinct from the immutable `VirtualFile`.
- **PluginProcessingFrame** — the whole-plugin working object passed through the `PluginPipeline`: `{spec: PluginSpec, vfs: VirtualFile[], frames: FileProcessingFrame[], templateContext}`. A `PluginProcessor` reads across all `frames`; `templateContext` carries the render placeholders (release variables + assembled bootstrap payload values) from `pluginAssembleBootstrap` to `pluginRenderTemplates`.
- **VirtualFile** — an immutable VFS entry `{path, sourceFiles: SourceFile[]}` (defined above).
- **SourceFile** — a contributing physical source file (defined above).
- **FilenameDirective** — the tilde-fenced token segment in a source filename. Form: `name~token[~token...]~.ext` — tokens separated by tildes, opened by a tilde after the base stem and closed by a trailing tilde before the extension. The closing fence contributes no token. Example: `bootstrap-core-policy~target-claude-only~overwrite~.md` -> `bootstrap-core-policy.md`, conditions {target-claude-only, overwrite}.
- **DirectiveToken** — one token inside a `FilenameDirective`; kinds: `OrderToken`, `TargetOnlyToken`, `IdeOnlyToken`, `SetOnlyToken`, `OverwriteToken`, `ProfileOnlyToken`. Every selector kind carries its own namespace prefix, so none can be read as another.
- **TargetOnlyToken** — a `DirectiveToken` kind restricting a source file to one exact IDE target (`target-claude-only`). It matches `spec.name` exactly and is unaffected by which set is building (FR-ARCH-0023).
- **IdeOnlyToken** — a `DirectiveToken` kind restricting a source file to every target of one IDE family (`ide-copilot-only` = `copilot` + `copilot-standalone`), the families derived from the target names by stripping any `-standalone` suffix (FR-ARCH-0023).
- **SetOnlyToken** — a `DirectiveToken` kind restricting a source file to one plugin set (`set-qe-only`). Validated by shape only, so filename parsing never consults the plugin-set configuration (FR-ARCH-0025).
- **ProfileOnlyToken** — a `DirectiveToken` kind that restricts a source file to one named profile (e.g. `profile-lightweight-only`), namespaced to keep it distinct from the target, IDE and set kinds. A file so restricted is emitted only when that profile is active.
- **SourceFileConditions** — the resolved conditions on a `SourceFile` (e.g. overwrite, target scoping) derived from its `DirectiveToken`s.
- **ModelVocabulary** — a per-IDE map (pure data) from logical model key to that IDE's model identifier, consumed by that target's model-normalization processor. When a profile is active and declares a block for the target, that block replaces this built-in map entirely; see **Effective model vocabulary** for what resolution consults. It is data, not a branching discriminant (FR-ARCH-0005).
- **Release**, **Domain** — defined above; each is a named type.
